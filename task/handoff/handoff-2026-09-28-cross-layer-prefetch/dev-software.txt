A software team maintains a service that processes invoices from several suppliers. Duplicate requests sometimes arrive after a network timeout. The database records a payment, but a separate notification service may fail before the customer receives confirmation. The team wants to make retries safe without redesigning every component at once. Explain a possible state machine for receiving an invoice, validating it, recording a payment, and sending a notification. Discuss idempotency keys, transaction boundaries, and how to detect inconsistent records. Suggest a staged testing strategy that includes process crashes and delayed messages. Describe what an operator should see when manual intervention is required, and explain which metrics would reveal recurring failures.
