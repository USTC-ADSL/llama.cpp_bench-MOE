# Bounded CPU layout and execution study

Existing online CPU aliases immutable canonical Q4_0 DMA weights; CPU_REPACK is available but not used for routed Experts. CPU_REPACK MUL_MAT_ID uses row GEMV while ordinary MUL_MAT uses GEMM for groups of four or more rows. Full tensor setter only, no partial3D updates. Do not alter native default or rewrite source bytes.

Controls: original canonical-ID; bounded8-Expert CPU_REPACK-ID with whole-group setters and bounded canonical staging; one-Expert CPU_REPACK ordinary MUL_MAT, keeping all routed rows for that Expert together. All three gate/up/down matrices participate; weights converted only after current actual route is known. One reusable target workspace per request, not per layer. Group-ID has at most8×4.64MiB packed targets plus one projection staging (~12.38MiB); grouped-MM has one Expert triple (~4.64MiB), no source staging. Both reuse the current CPU activation arena. Tail group padding is valid repeated source data, unused slots never routed. Last-token layer retains canonical control initially.
