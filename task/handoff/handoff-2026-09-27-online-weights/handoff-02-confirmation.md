## Newly identified memory issue; next necessary fix

Explicit observer+arena/staging allowance72.26MiB is NOT total extra-memory proof. Native maxrss~580–585MiB, online~3752–3954MiB during initialization. Both use CPU graph76.19MiB; native HTP graph12.65MiB versus online5.07MiB. Online raw routed DMA source6682.5MiB replaces source representation, not extra converted cache. GPU shared has only one layer, not24 copies.

Root path: src/llama-model.cpp:1729 always calls ml.init_mappings(true,...). src/llama-mmap.cpp:478-479 uses MAP_POPULATE for prefetch when lazy ranges empty. Online loader keeps unused original Expert tensors mapped even though callback consumes separately owned canonical DMA. This unnecessarily faults another source mapping into RAM, evicts/swaps CPU output weights, and invalidates the desired total-memory interpretation. Runtime madvise(DONTNEED) currently only drops its own source mapping PTEs after each layer copy, not global page cache or the model loader's later mapping. Qwen2MoE experts are not marked TENSOR_READ_LAZY (src/models/qwen2moe.cpp:47-49), so merely setting lazy_mode ON will not solve this. Weight-manager policy could mark swap ranges but has unrelated scheduling side effects; avoid switching whole execution mechanism for this.

Suggested bounded fix: expose opt-out for whole-mmap prefetch (default remains current behavior; add trailing no_mmap_prefetch bool in llama_model_params/defaults, pass !flag into init_mappings). Online should opt out, and evaluate matched no-prefetch native baseline too. During canonical source import, release each copied routed matrix mapping and advise file pages DONTNEED to avoid a second physical file-cache copy; release only owned mapping, keep source file unchanged. A source optional fd/callback can release after each92.8MiB matrix instead of after a278MiB layer. Need independently test memory, count advice failures, verify logits against current/reference, and rerun first-pass performance.
