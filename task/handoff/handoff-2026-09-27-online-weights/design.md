# First-pass online weights: design and validation contract

Scope confirmed by user: single-request full Transformer prefill, fd8657d6, Qwen1.5-MoE Q4_0. Preserve extension points for decode. Target approximately 200 MiB extra application storage over one model representation; disclose relaxation and process/driver limits. No target prompt route capture, no prompt-specific bank preparation, no converted Expert cache warmup before first request. Model initialization and source UFS reading are reported separately from first-prefill latency; online decision, preparation, transfers, synchronization and first-use graph work stay inside it. Compare with an already loaded native NPU model, not with a deliberately streamed slow baseline.

Existing dynamic runtime consumes actual router outputs but recreates small converted banks each wave. Historical128 result6110ms versus native622ms is a negative baseline. Existing HTP setter repacks on CPU; OpenCL partial Expert setter also converts on CPU; full OpenCL setter uses a conversion kernel. Historical source-memory triple preparation: CPU0.951ms, GPU2.841ms, HTP1.237ms; these are prior microbenchmarks, not current online costs.

Candidate A: canonical GGUF source, reusable bounded target banks, optimized host conversion, independent preparation/execution per backend. Candidate B: the same immutable canonical Q4_0 bytes in shared DMA as the sole complete Expert source, CPU reading them directly and HTP dequantizing/reordering only the selected tiles into its existing VTCM compute scratch. Candidate B is NOT a prepacked HTP bank: all Expert bytes remain canonical and placement-independent, and both CPU/HTP consume that one representation. GPU shared weights are prepared in a bounded layer working set after request start. Source loading into shared DMA is model initialization, independent of prompt. Do not retain another full CPU/private canonical copy; report file mapping/page residency separately and the transient source-loading peak.

Prototype B first on gate/up/down matrix shapes, real GGUF bytes, fixed synthetic inputs and Expert IDs: compare canonical fused HTP compute against resident tiled HTP and timed source-to-tiled preparation+compute. Require exact source byte round trip, nonvacuous outputs and numerical comparison against unchanged HTP computation plus dequantized reference. Test multiple experts/rows, tail shapes, unsupported-op rejection and ordinary packed-path regression. No model integration or speedup claim until this passes.

Then compare complete Expert and layer costs before selecting runtime path. Reuse the existing performance model's per-backend cost structure, but do not reuse its resident whole-request confidence guarantee for a different layout and online layer policy. Account conversion exposure explicitly. Current-layer route counts may inform decisions; future layers are unknown. Record actual Expert ownership and route counts in each run.

Full-model confirmation uses fresh prompt texts and first request only per process with frozen policy/code; independent native brackets, same token workload, all full logits retained. Development inputs and final confirmation prompts remain separate. No retuning on final confirmation. A faster conversion microbenchmark alone is not a successful online inference result.
