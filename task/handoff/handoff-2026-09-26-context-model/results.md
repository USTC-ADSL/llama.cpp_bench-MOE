# 完整模型成本校正与执行路径选择

fd8657d6，Qwen1.5-MoE Q4_0，单请求完整 24 层 Prefill（包含 attention、真实 router、shared/routed、KV 与最终 logits）。先用 technical prompt 校准并冻结，再用新编写的 ecology prompt 验证；没有用 ecology 或历史 narrative 耗时重新拟合。权重在计时前准备到选定后端，仍不是在线迁移或冷启动 TTFT。

## 模型设计

保留首版 86 系数的分组成本模型，以实际完整模型运行校准三个长度节点（128/256/512）和三种执行族：CPU 小尾组、GPU 小尾组、routed 全 NPU + shared GPU。每族加入三个后端倍率、一个 host 倍率、一个非 FFN 残差及经验波动量。后端倍率在 `max` 之前应用：

`T_custom(P) = Σ_layer [max_b α_family,b × f_b(P) + β_family × h(P) + outside_family/23]`

最后一层 FFN 因只请求最后位置的 logits 仅计算 nt=1，使用基础预测、不加 outside；其余 23 层分摊 outside，因此不会把全模型残差加 24 次。outside 是总耗时减 gather/Expert 墙钟/聚合，含 attention、框架、KV、logits 等，不能称为单独测出的图边界开销。当前测试的常规层均选同一执行族，未验证任意混合执行族的残差可加性。

原生 NPU 预测 = 同长度完整模型校准时间 + 当前路由基础 NPU 工作预测相对校准路由的变化。只有 custom 预测 + 经验波动 + 决策预算低于 native 预测 − 经验波动时，才在**加载权重前**选择异构路径，否则直接加载原生 NPU；不先加载三份权重再免费切换。

波动量取 max(1 ms、A/B 中位数差的一半、进程内绝对偏差的 90 分位)，不是统计置信区间。节点之间线性插值，拒绝 128–512 以外的外推。部署 JSON 11715 bytes（含源文件哈希），无需引入大型学习模型。固定参数 SHA256：`d30363c298e1cce9dfb605f65bc81860e6dd70f4827cb124f629d763f81e0cdb`。

256 下新旧模型的完整 Expert 映射**相同**；两者时间差含跨进程扰动及新方案额外计入的决策成本，不能声称校正在该长度改进了放置。512 首版相对 NPU 仍慢 7.69% / 7.50%，校正后才转为正收益。新方案六个进程的完整模型预测相对实测误差绝对值均低于 2%（不含决策时间）。所有实际选择均为 custom；另做一次强制 native 的 auto 加载功能检查，不能把它写成实际模型触发了保守回退或验证了回退收益。

## 具体分配

层号从 0 开始。每层按捕获路由的 `(token 数, Expert ID)` 排序，取低负载组；并非 token 阈值，也不是指定语义类型。完整 60 个 Expert ID 的 owner 在 `evidence/ecology-*-plan.json.gz`。

| 输入 | 0–22 层常规方案 | 例外层 | shared |
|---|---|---|---|
|128|最低负载 24 个 → CPU，其余 36 个 → NPU|22 层为 CPU 32 / NPU 28|GPU|
|256|最低负载 16 个 → CPU，其余 44 个 → NPU|22 层为 CPU 24 / NPU 36|GPU|
|512|最低负载 8 个 → CPU，其余 52 个 → NPU|21/22 层为 CPU 16 / NPU 44|GPU|

23 层均 routed → NPU、shared → CPU；该层 FFN 仅 nt=1。CPU/GPU/NPU 分支并行，完整模型继续执行真实 router，并不回放捕获的 Expert ID。

## 为什么大输入收益恢复

512 的 A 组均值阶段归因如下；均值不能与上表中位数直接相加：

| 阶段 | 首版 ms | 新方案 ms |
|---|---:|---:|
|Expert 并行墙钟|474.27|481.66|
|gather|81.95|23.37|
|聚合|62.75|18.67|
|其余完整模型部分|353.17|271.60|
|总计，不含决策|972.13|795.30|

关键不是 Expert 墙钟降低，而是**所选执行形态改变了完整模型的 host 和非 FFN 成本**。首版主要把低负载 24 个 routed Expert 给 GPU、shared 给 NPU；校正后以更小的 CPU routed 尾组配合 GPU shared。新方案 CPU/NPU/GPU 计算跨层总量约 303/463/461 ms，CPU 小组能被两条加速器分支覆盖。未隔离 CPU 频率、共享缓存属性或具体访存路径，不能把阶段差异进一步写成已证实的硬件根因。

## 轻量反馈

按层为三个后端和 host 保存 4 个倍率，共 96 个 double；在本次执行前预测，结束后用 EWMA 更新，α=0.5、比值限制 0.25–4。输入用上次真实路由计数，首轮用捕获参考；不使用本次观测预测本次。首次调用或新增 Expert 图的观测不更新，稳定的第二次预热可更新首个正式样本。

六个独立反馈进程的 FFN 总时长 MAPE 平均从 **4.06% 降至 2.35%**，预测/更新核心平均开销 **81 µs/次完整模型调用**。各长度 A/B：128 为 4.15%→1.14% / 7.42%→5.76%，256 为 2.88%→1.10% / 3.04%→1.21%，512 为 2.80%→2.46% / 4.06%→2.40%。记录 JSON 构建/落盘不计入该核心开销。

反馈仅修正后续预测，没有改变权重 owner，不能把这部分称为在线调度吞吐收益。首次尝试将图分配冷启动学入反馈而恶化预测，保留在 `evidence/pre-feedback-fix/`；根因与修正见 [Bug 简报](../../../docs/bugs/2026-09-26-moe-feedback-cold-allocation.md)。突发缺页等扰动仍可能使反馈滞后。

## 正确性、内存与边界

24 个确认进程及 native 加载检查退出 0；同一二进制/库/prompt 哈希、训练源哈希、基础模型完整内容、Python/C++ 逐层计划和成本、真实 pair 账本、反馈逐样本状态重放均通过。各策略 A/B logits 一致，异构每轮 logits 一致，自动方案与相同映射的强制 custom 输出逐字节一致；强制 native 加载与原生 NPU 输出一致。

128/256/512 的 top-1 均与 CPU 捕获参考一致，分别为 31366/3015/2083。新方案全 logit NRMSE 为 3.863% / 2.305% / 6.439%，原生 NPU 为 3.603% / 2.284% / 6.108%。因此这里验证了执行一致性，没有完成任务质量或困惑度评估，更不能宣称全部数值与 CPU 等价。

共享 Expert 激活池为 43.76 / 87.51 / 175.02 MiB；不是总额外物理内存或 RSS 上限。计时区间无新增 Expert 图分配，新方案 major faults 为 128:0/0、256:0/2、512:0/0；逻辑常驻未 mlock。没有为本模型额外保留三套 Expert 权重。

下一步优先验证跨 prompt/更长输入及每层预测，而后将真实当前路由、驻留可用性约束接入在线决策。权重转换保持独立模块，只向决策器提供可执行候选和实测准备成本；不把转换过程本身塞入当前回归模型。本阶段未验证 Decode、多个请求、64 或超过 512 的输入，也未保证全部场景正收益。
