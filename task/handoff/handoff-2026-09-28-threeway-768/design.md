# Bounded three-way 768-token experiment

User requested a new experiment: shared on NPU, low-load routed experts on CPU, remaining routed work divided between GPU and NPU. This independently authorized scope reopens only this new family; prior completed studies remain frozen.

Device fd8657d6, Qwen1.5-MoE Q4_0, complete 24-layer single-request 768-token prefill. Use the existing resident fullmodel-oracle runtime, shared activation arenas with lifetime reuse, direct callback IO, fused serial host reduction and overlapping branch input preparation. No kernel/routing changes and no online weight conversion claim. All custom modes use routed NPU/shared CPU for the terminal one-token layer, matching historical controls.

Six candidate policies: CPU receives the lowest-load 4 or 8 active experts per ordinary layer. Sort the remainder by descending token count (expert ID tie-break), and choose a nonempty proper prefix whose token-pair sum is nearest 15%, 30%, or 45% of the remainder. GPU receives this hot prefix; all other experts and shared reside on NPU. Inactive experts remain assigned to NPU so real online routing may differ safely from the offline capture. Expert ownership is fixed before timing, but actual router probabilities/IDs are recomputed during inference. This tests whole-expert placement, not splitting one expert across devices.

Development uses the existing technical prompt and recorded 768-token CPU route statistics. Native NPU brackets the old CPU-tail4/shared-GPU and GPU-tail24/shared-NPU controls plus the six candidates. Every process has two warmups and six formal synchronized requests. Select the candidate with the minimum complete-request median; freeze before inspecting two newly authored confirmation inputs (wetland, foundry). Each confirmation input runs native, both old placements and the selected candidate in forward/reverse independent-process order, six requests each. Preserve all observations, including negative results. No tuning on confirmation data. All modes use the same source/binary/library versions.

Verify device identity, prompt token IDs, exact requested placements, immutable artifact hashes, finite full logits and within-process repeat stability. Report same-path cross-process logits and cross-backend relative L2/top1 without claiming model-quality equivalence. Times: per-backend compute windows include backend submission/synchronization; aggregate them over layers, and separately report sum of layer maxima, parallel expert wall, gather, combine and outside-FFN residual. Parallel times must not be added as sequential components. Gather overlaps branch compute; the separately recorded gather field must retain the runtime's accounting interpretation.

Protocol hashes source, artifacts, prompts and route source before measurements. Rebuild only necessary existing targets and the standalone oracle. Use the existing fixed device project directory after confirming it is absent/idle, mark ownership, archive outputs with hashes, then remove only verified owned files. Keep full host evidence. Capture/plan construction/weight preparation are outside resident inference timing and reported as such.
