# Host 执行优化与同前缀数值诊断

fd8657d6、Qwen1.5-MoE Q4_0、单请求完整24层 Transformer。沿用上一轮冻结的 Expert owner，不改变 router、权重格式或常驻位置，也没有用本轮时延重新拟合放置模型。性能区间包含 attention、router、Expert、聚合和最后位置 logits；权重准备、离线路由及加载不计入。所有策略仍为可选开关，默认不增加聚合线程或启用 gather overlap。

## 同前缀诊断

为常驻 harness 增加可选16步续写：保留最后一次 prefill 的 KV 与权重，激活图缓存键增加 nt，使同一 bank 能切换到单 token 图。先由 CPU 生成16个 token，再让原生 NPU、异构强制接受相同 token；初始 prefill 加16次 decode 共比较17个相同前缀。另保存各策略自由 greedy 续写。质量调用在性能计时之后，未把其延迟算入吞吐。

| Prompt / 输入 | 后端方案 | 与 CPU top-1 一致 | 平均 KL(CPU‖方案) | CPU greedy token 平均 NLL 差，nats |
|---|---|---:|---:|---:|
| museum128 | 原生 NPU | 14/17 | 0.00631 | +0.0160 |
| museum128 | 异构 | 15/17 | 0.00511 | −0.0188 |
| programming768 | 原生 NPU | 14/17 | 0.01319 | +0.0217 |
| programming768 | 强制异构 | 15/17 | 0.01538 | +0.0570 |

KL 使用17个位置，NLL 差使用实际输入的前16个 CPU greedy token；这不是人工参考语料，也不是困惑度。异构多一个 top-1 一致位置不等于质量更高。不同 top-1 的位置，CPU 自身第一/第二候选差距约0.043–0.316 logits，CPU 的第一候选在对照方案排第2或第3。原始 logit NRMSE 对整体平移敏感，不能直接当作概率分布误差。

例如 museum128 的16-token续写：CPU 为“账本记录了1800年至1900年间的交易”，异构为“账本记录了1830年到1930年间的”，NPU 为“1800年，店主记录了每笔交易，包括顾客姓名”。programming768 的原生/异构续写相同，但与 CPU 不同。这证实数值差异会导致生成分叉；没有据此确认任务质量等价或下降。下一步需要带人工参考的质量/困惑度测试。

10个诊断进程全部成功、同前缀及有限 logits 审计通过。六组当前初始 prefill logits 与上一轮 CPU/NPU/custom 存档逐字节一致，说明差异不是本轮续写改造引入。另测 lifetime 复用后的16步异构输出，与未复用版本逐字节一致。

## 聚合线程数：局部变快，总体未获益

新增常驻线程池，按互不重叠的 token 区间分工，保持每个 token 内原有4路 FMA 和 shared 加法顺序。线程完成后才返回 callback/复用 arena。technical768 上比较2/4线程，各12次ABBA；2线程吞吐+0.85%，4线程−0.60%，因此冻结2线程后才进入新 prompt 确认。

每个确认进程两次预热后运行 `[单线程,双线程,双线程,单线程] × 3`，每个条件六个样本；每个 case 两个独立进程。线程唤醒、分发与等待全部计入聚合及总时间。

| Case | 聚合均值 单→双 ms，A/B | 相对同进程单线程的完整模型吞吐变化，A/B |
|---|---:|---:|
| museum128 | 4.15→3.61 / 4.19→3.66 | −0.50% / +1.45% |
| museum384 | 13.46→10.49 / 13.24→11.75 | −0.81% / −1.39% |
| museum768 | 27.68→21.45 / 27.51→21.61 | −0.14% / −0.40% |
| programming768 | 29.65→21.96 / 29.68→22.36 | −0.07% / −0.60% |

7/8进程的总均值变慢，因此不把线程池列为已获益的 paper 技术点，默认保持单线程。768时聚合省约6–8ms，但 gather 与 Expert 阶段通常合计增加约6–11ms，说明局部节省被其他阶段抵消。未测核心频率/缓存计数器，不能把补偿变化进一步确定为某一种硬件原因。Android worker 单测覆盖2/4/8线程、边界 token 数、重复调度和异常恢复；同进程所有 logits 及前一版本输出逐字节一致。

## 每个后端独立准备输入并启动计算

现有方案虽并行计算，却先串行完成所有后端 gather，再同时启动计算。新方案仍串行完成路由分组与图元数据准备，随后由各分支在自己的激活区内完成 gather 并立即计算；直到全部完成才按原顺序聚合。不同后端不共享写入地址，不增加权重或激活副本。

理想化执行依赖由 `Σ_b G_b + max_b C_b + H` 改为 `max_b(G_b+C_b) + H + 调度成本`，其中 G 是后端输入准备，C 是计算，H 是最终聚合。真实设备存在并发争用，仍以完整模型实测为准。shared GPU 不必再等待 NPU routed 输入整理完毕；这与更改 Expert owner 是两个独立维度。

technical768初测的总均值1128.975→1089.537ms（吞吐+3.62%），三组ABBA全部获益。准备+计算合计736.887→699.881ms。原屏障方案的 CPU/NPU/GPU gather 跨层均值约3.12/37.78/12.69ms，GPU在138次常规层观测中114次为最后完成分支；提前启动后，即使部分单分支 gather 变慢，仍可缩短整层等待。各后端实际计算/访存也可能随并发改变，不能把理想式当作严格性能上界。

确认沿用相同12次ABBA与两进程设计，始终单线程聚合，不把已失败的聚合并行组合进去：

| Case | 完整模型均值 屏障→重叠 ms，A | 完整模型均值 屏障→重叠 ms，B | 吞吐变化 A/B |
|---|---:|---:|---:|
| museum128 | 374.490→375.569 | 379.450→377.889 | −0.29% / +0.41% |
| museum768 | 1122.212→1099.305 | 1175.403→1143.713 | **+2.08% / +2.77%** |
| programming768 | 1337.236→1325.124 | 1301.837→1277.803 | **+0.91% / +1.88%** |

四个768进程的均值均获益，12组配对ABBA中11组总时间下降；programming-A第一组反而慢9.15ms，保留该结果。因此支持长输入下约0.9%–2.8%的局部增益，不是每次调用都加速。128没有稳定收益，尚未验证256/384的gather重叠收益，默认保持关闭。

两个768 case 的准备+计算均值 A/B 分别为：museum 729.889→703.839 / 764.122→732.080ms；programming 899.689→879.187 / 861.788→838.532ms。以museum-A为例，GPU在138次常规层观测中130次最后完成。屏障方案先完成约38.3ms跨层NPU gather后才能启动GPU分支；新方案允许GPU shared与这段准备重叠。聚合约27ms不变，支持主要收益来自输入准备与计算依赖的调整。

另用同批二进制在两个768 case 的异构进程前后各测一次原生NPU（各6次计时）。按进程中位数，museum强制异构重叠相对原生+5.85%/+5.97%，programming仍−12.55%/−5.33%。跨进程运行状态存在漂移，这些不是重叠优化的因果收益；其因果对照应使用上表同进程结果。**本次没有让长输入异构普遍超过原生NPU，原模型的保守回退仍有必要。** 所有性能表均为固定放置纯执行，不额外计入离线决策成本。

全部重叠确认的逐轮输出与屏障版本、上一轮同owner输出逐字节一致；原生控制输出与旧原生存档一致。开启overlap与lifetime后，额外16步teacher-forced续写也与旧异构版本逐字节一致。激活池仍为128的28.254MiB、768的169.523MiB，没有因overlap另留激活副本；这些数仍不代表进程总额外内存。

另做一次全部24层 routed/shared 同在NPU的128-token单分支回归（4次ABBA）：开关overlap输出逐字节一致，并与上一轮同图输出一致，用于覆盖native输入与shared输入别名路径。此回归不用于声称性能收益。

计时注意：overlap模式下 `expert_wall_us` 包含分支 gather，因此阶段对照始终使用 `gather_us + expert_wall_us`，不能单独比较前者下降，也不能把 `backend_gather_us` 再加一次。记录的 branch interval 是 host 调用包围时间，不是硬件 kernel 时间戳。

## 证据与复现

质量：`tests/run-moe-quality-study.py`、`tests/summarize-moe-quality-study.py`。线程池：`tests/run-moe-host-parallel-study.py tune/confirm`、`tests/summarize-moe-host-parallel-study.py`。gather：`tests/run-moe-gather-overlap-study.py pilot/confirm`、`tests/summarize-moe-gather-overlap-study.py`。各 summarizer 参数为本任务目录；完整命令、设备温度快照、二进制/库/输入哈希在运行 manifest 内。

未锁频、不筛除慢样本；ABBA减轻时间漂移但不是统计置信区间。质量、线程池、gather分属三个先后构建的二进制批次，各批次内核对一致性，不跨批次硬称同一可执行文件。当前模型768仍选择原生路径；强制异构实验不代表已更新在线调度器，也没有包含在线权重迁移成本。

## 对后续调度模型的含义

下一步应将每个后端的输入准备时间、可开始时间与计算时间一起预测，并将“统一准备屏障/分支独立准备”作为执行候选，再用独立训练prompt重新校准。线程数不能按聚合局部收益独立决定，要用完整调用残差判断。权重转换依旧独立输出准备成本和驻留约束，不必塞入当前回归主体。性能更深入的方向是降低共享激活的实际host读取/写入量或在后端聚合，再考虑分块流水；本轮只隐藏部分等待，没有减少gather字节数，也没有证明带宽争用已解决。
