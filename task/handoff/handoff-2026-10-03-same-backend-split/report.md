# 同一后端上的逐层显式同步与数据传递

在本次 36 层真实激活链 microbenchmark 中，逐层显式同步并传递激活，相比同一后端的一张连续图：GPU 耗时增加 62.29%、整机能量增加 11.76%；NPU 耗时增加 15.69%、能量增加 8.87%。CPU 未观察到稳定的能量负优化：两轮耗时低约 2.5–3.0%，能量变化为 −3.16% 和 +1.53%。因此不应声称拆分对所有后端都必然更差。

## 对照定义

36 层 Qwen2.5-3B 权重常驻；每层为完整 Attention+FFN，包含 KV 写入、Flash Attention 和两次残差。固定最初输入及 256 项历史 KV，每次 pass 都通过真实中间激活顺序计算 36 层。不是把独立层耗时相加，也不是独立 synthetic input 逐层拼时长。无 embedding、最终 norm/head、sampling，不将 pass 称为生成 token。

| 模式 | 图提交 | 显式同步 | 层间输入 |
|---|---:|---|---|
| single_graph | 1 次/pass | 全图结束 | 直接引用上一层输出 |
| split_shared | 36 次/pass | 每层结束 | 直接引用上一层输出，无激活拷贝 |
| split_copy | 36 次/pass | 每层及每次 copy 结束 | 拷贝到下一层独立输入，共 35 次 |

每次激活为 2048 个 FP32，即 8192 B；35 次共 286720 B/pass。使用同设备 `ggml_backend_tensor_copy_async`，后端支持时走 native copy，否则按 API 安全回退；没有人为强制 GPU/NPU 经 host 往返。

三模式复用完全相同的权重、节点顺序及已分配 buffers。组合图保留各层原始拓扑序，只有层输入引用和 graph submit 边界不同。没有重复加载权重、每 pass 重新分配 tensor 或增加 A/F 内部边界。此基线是复用 microbench 层图组成的单图，不等同于 llama 全模型的优化内存规划，也不应直接用于判断全模型端到端后端排名。

## 实测结果

以下为首轮，时间和能量均对应完整 36 层执行一次：

| 后端 | 模式 | 耗时 ms | 平均整机 W | 能量 J | 相对单图耗时 | 相对单图能量 |
|---|---|---:|---:|---:|---:|---:|
| CPU | 单图 | 42.0270 | 7.8129 | 0.328351 | — | — |
| CPU | 逐层同步，共享输出 | 42.1477 | 7.8203 | 0.329607 | +0.29% | +0.38% |
| CPU | 逐层同步＋拷贝 | 40.7846 | 7.7962 | 0.317965 | −2.96% | −3.16% |
| GPU | 单图 | 39.7174 | 8.8265 | 0.350565 | — | — |
| GPU | 逐层同步，共享输出 | 64.1364 | 6.0810 | 0.390014 | +61.48% | +11.25% |
| GPU | 逐层同步＋拷贝 | 64.4578 | 6.0782 | 0.391788 | +62.29% | +11.76% |
| NPU | 单图 | 106.1845 | 5.4544 | 0.579168 | — | — |
| NPU | 逐层同步，共享输出 | 113.7018 | 5.2896 | 0.601435 | +7.08% | +3.84% |
| NPU | 逐层同步＋拷贝 | 122.8396 | 5.1329 | 0.630529 | +15.69% | +8.87% |

GPU 的显式同步＋拷贝总差为 +24.740 ms、+0.041223 J/pass；NPU 为 +16.655 ms、+0.051360 J/pass。将总时间差平均到 35 个边界，分别约 707 µs 和 476 µs；这包括提交、等待和可能的图优化差异，不是纯 memcpy 延迟。

CPU 补测使用同样顺序和默认设置，仅补 CPU 一轮：

| 模式 | 耗时 ms | 能量 J | 相对单图耗时 | 相对单图能量 |
|---|---:|---:|---:|---:|
| 单图 | 41.3527 | 0.317676 | — | — |
| 逐层同步，共享输出 | 41.1722 | 0.319292 | −0.44% | +0.51% |
| 逐层同步＋拷贝 | 40.3297 | 0.322534 | −2.47% | +1.53% |

CPU 的小幅时间下降复现了，但能量变化符号不同。未继续分解这一小幅时间差的缓存/图执行原因，不能称为 copy 本身带来加速，也不能强行报正的拆分开销。

## 开销定位的范围

GPU 在不拷贝、只切成 36 次图提交与同步时，已增加约 24.419 ms，接近 split_copy 的全部差距。这支持主要代价来自图执行边界及同步限制，而非仅 280 KiB 激活字节量。

NPU 仅拆图同步增加约 7.517 ms，加入显式 copy 后又增加约 9.138 ms。另做的短诊断将 copy API 和等待一起计时，35 次约 11.166 ms/pass；由于诊断与功率窗口分开执行，不把它与窗口差值当作严格可相加分量。CPU 和 GPU 的相同 copy 诊断分别约 0.026 ms 和 0.192 ms/pass。

GPU 单图和拆图输出有约 3e-5 的 relative RMS 差异（最大绝对差约 0.00226），通过 1e-4 门限；因此可能存在 backend 图范围内融合/累积差异，不能声称其差距全为主机同步函数自身耗时。CPU/NPU 输出逐元素完全一致。所有模式计算量与图节点数相同。

## 条件、验证与产物

设备为用户更新后的 `192.168.50.178:37949`，PKR110/SM8750，模型 `/data/local/tmp/models/Qwen2.5-3B-2K/ggml/weights.gguf`。CPU 仍为核 6–7、2 线程，CPU/GPU 默认 governor，不设置频率；NPU 默认 MAX corner 请求、DCVS-off。功率窗口内 CPU 后端及 NPU host 采到 2.4384 GHz，GPU host 为 1.0176 GHz、GPU 1.1 GHz。

每模式先 warmup/正确性检查，2 秒稳定，5 秒电池采样；另有 5 次短时计时和 5 次边界诊断。加载、构图和正确性检查不计入采样。E=窗口平均功率×窗口时间/执行次数；是亮屏整机估计，沿用报告电流 mA 和双串电压 ×2 近似，不扣 idle。每模式一窗口，CPU 因首轮出现小幅反向变化额外补一轮；没有置信区间。

先用两层在三后端验证所有模式输出完全相同，再用 36 层测量。每个 split_copy 模式都核验 35 个边界逐字节一致，输出 finite，无休眠，能量积分独立复算通过。设备默认频率/governor未变，恢复原屏幕/3h超时并释放 wake lock；设备目录只保留 7 个部署二进制/库。

原始数据在 `results/`，CPU 补测在 `cpu-repeat/`，小图正确性在 `pilot/`。主表为 `results/analysis/results.csv`，百分比及诊断为 `results/analysis/summary.json`，图为 `results/analysis/same-backend-split.png` / `.pdf`。两轮 CPU 均完整保留，没有择优替换。
