# MoE 异构推理技术点

实验范围：Redmi K80 Pro（fd8657d6）、Qwen1.5-MoE Q4_0、单请求、固定 prompt、完整 Transformer。以下为已有实证支持的论文技术候选，不代表已完成相对现有工作的创新性论证；各项收益来自不同对照，不能直接相加。

| 技术点 | 解决的问题 | 主要方法 | 一句话效果 |
|---|---|---|---|
| 路由负载与 shared Expert 联合放置 | 按单 Expert 延迟或统一 token 阈值分配，难以平衡整个 MoE 层的并行关键路径。 | 根据离线路由统计共同选择 routed Expert 分组和 shared Expert 后端，将每个 Expert 的转换后权重常驻在选定后端，执行真实在线路由。 | 128-token 完整模型中，常驻异构方案相对全 NPU 的两组吞吐分别提升约 31.3% 和 33.2%，但该收益不包含在线权重迁移成本。 |
| 跨后端共享激活 | 分散执行后，输入上传和输出读回侵蚀 Expert 并行收益。 | CPU/GPU/NPU 通过共享 DMA 内存访问激活，gather 直接写入、聚合直接读取，并显式保证完成顺序与缓存可见性。 | 256-token 两组对照中端到端分别减少 23.1 ms 和 41.6 ms，logits 逐字节一致，但计算图边界与 host 聚合开销仍存在。 |
| 大激活回调的直接读写 | 大张量临时分配、初始化和复制产生额外 host 开销，导致调度成本随输入规模出现明显变化。 | 借用现有输入 tensor，直接向已有输出 tensor 聚合，避免每层重新分配输入与结果数组。 | 256-token 同进程 ABBA 实验平均减少 41.75 ms（6.05% 延迟），minor fault 从约 23,970 次降至 371 次，六组均获益且输出逐字节一致；128 token 未显示稳定额外收益。 |
| 按执行生命周期复用共享激活池 | 缓存每层执行图时同时保留各层激活，内存随层数增长，限制多后端执行。 | 将图元数据与激活存储解耦，各后端按最坏路由容量预留一份共享池，在上一层计算和聚合完成后复用。 | 256-token 的 Expert 激活缓冲从 1259.48 MiB 降至 120.25 MiB（减少 90.45%），128-token 池为 55.01 MiB，输出不变；尚不主张稳定延迟收益。 |
| 保序融合 routed/shared 聚合 | 分别累加 top-k 输出和 shared 输出会反复读写结果数组，放大 host 聚合开销。 | 按 token 在寄存器中保持原 top-k FMA 顺序，融合 shared 加法并仅写回一次结果。 | 256-token 两个独立进程共 12 组 ABBA 均获益，聚合均值约 31–36→11 ms、端到端均值减少 20.75/29.45 ms（3.56%/4.76%），输出逐字节一致；128-token 端到端收益尚不稳定。 |
| 按组按需转换的权重驻留控制 | 各后端权重格式不同，完整保留三份转换权重会造成内存膨胀。 | 保留不可变源权重，通过在线放置接口按 Expert 组转换并维护受限后端工作集，支持 Prefill/Decode 阶段切换。 | 128-token 功能验证中转换后 Expert 权重峰值约 92.82 MiB、采样激活约 17.54 MiB，但重复转换使该路径尚未取得吞吐收益，不能与常驻方案的加速混为一谈。 |
| 分组关键路径的轻量分配模型 | 固定 Expert 归属在路由和输入长度变化时产生 CPU 长尾，逐个 Expert 阈值无法决定 shared/routed 的整体分配。 | 用 86 个系数预测并发后端分组与 host 成本，联合选择低负载 Expert 组和 shared 后端；以独立 prompt 验证，权重预先准备。 | 未参与拟合的128-token完整模型吞吐提升31.5%/38.0%；512-token将旧固定方案38%–42%的吞吐损失缩小至约2%，但尚未超过原生NPU，后续需校准整模型host与图边界成本。 |
| 完整模型环境下的成本校正 | 孤立 FFN 预测遗漏执行形态对 host 和非 FFN 成本的影响，导致大输入下选错 routed/shared 分工。 | 以少量完整模型观测校正后端、host 与非 FFN 残差，加载前联合选择 Expert 分组及原生/异构执行路径；模型仅 11.7 KB。 | 新独立 prompt 的 512-token 吞吐由首版相对 NPU 下降约 7.5%–7.7%，转为提升 11.9%–12.5%（已计决策成本）；因果残差反馈另将 FFN 预测 MAPE 从 4.06% 降至 2.35%，尚不代表在线迁移收益。 |
| 有校准覆盖约束的长度自适应选择 | 不同长度的校准若混入不同 shared 后端，会对未观测的执行组合作错误插值。 | 固定各执行族的 shared 后端，保留旧节点，仅追加 technical 的 1024-token 校准；用经验波动余量在加载前选择异构或原生 NPU。 | 两个新 prompt 的 128/384-token 吞吐分别提升 39.2%–49.0% / 11.5%–21.5%；768 自动回退后相对原生为 −1.6%～+1.0%，尚不证明回退每次最优。 |
| 图内存活区间复用共享激活 | 跨层复用后，同一图内不同时存活的中间张量仍占用独立空间，使长输入激活池膨胀。 | 按含 view 别名的张量存活区间复用共享池槽位，固定最大形状布局并验证小形状绑定，保持输入及聚合输出存活。 | 相同 Expert 分配下，768-token 激活池从 262.53 降至 169.52 MiB（−35.4%），输出逐字节一致；尚未观察到稳定延迟收益。 |
| 按后端独立准备并启动 Expert 分支 | 计算虽已并行，统一输入准备屏障仍让 shared 分支等待其他后端的 routed gather，拉长关键路径。 | 在各后端独立共享激活区内完成 gather 后立即计算，将准备与其他分支计算重叠，最后保持原顺序聚合。 | 两个新prompt的768-token同进程对照中，四个进程均值吞吐提升0.91%–2.77%，12组ABBA中11组获益且logits逐字节一致；128无稳定收益，也未让所有长输入超过原生NPU。 |
| 联合决策中的候选代价复用 | 同时搜索 Expert 分组和执行策略时，重复特征计算与计划构造会吞掉并行收益。 | 缓存每层分组的数值代价，在候选间复用，仅为最终选择构造执行计划。 | Android 配对实验中，768-token 热态规划中位数约21.87→3.05ms（−86.1%），候选成本、分配和输出保持一致；该控制路径优化本身尚不构成独立创新性结论。 |
| 完整分配覆盖与预测误差保护 | 小组或单层校准不能保证整个请求的时间预测准确，微小的预测收益容易被运行状态波动反转。 | 联合校准Expert组大小、shared后端及准备策略，用独立输入的预测残差设置经验余量，收益不足时加载原生路径。 | 最终两份新prompt的128/256/512-token吞吐分别提升35.8%–43.1% / 24.1%–28.7% / 5.3%–9.8%（含决策）；768回退后为−0.74%～−0.06%，不保证逐次最优。 |
| 带误差保护的连续长度分配 | 精确长度校准无法直接覆盖300等真实输入，为每个整数长度重测成本过高。 | 在同执行族的相邻锚点间插值每层Expert组大小和路由代价，以少量区间中点校正非线性残差，保留经验误差余量和原生回退。 | 未参与拟合的300-token两份新prompt吞吐提升20.5%–25.5%，480提升14.3%–14.4%（均含决策）；704主动回退但仍有规划开销，不保证逐次零退化。 |
| 预加载状态的有界残差校正 | 相同路由在不同运行状态下耗时变化，固定预测偏差无法覆盖异构执行速度漂移。 | 以加载前可见CPU频率和温度修正原路径预测；独立验证决定启用状态特征或仅保留平均偏差，并保留域外回退和误差保护。 | 新prompt上异构预测MAPE由4.46%降至2.40%，128吞吐仍提升41.3%–43.2%；原生预测未改善，且本轮未证明新增调度吞吐收益。 |
| 单份源权重与片上按需转换 | 未知路由若在计算前物化后端布局，会付出转换延迟及副本内存。 | CPU 直接别名 canonical DMA 源权重，NPU 在 HMX 算子内仅将所需块转换到现有 VTCM 暂存。 | 两 Expert、128-token 单矩阵中，融合计算约0.75ms，低于CPU准备再计算约4.5–5.3ms，且与常驻packed NPU结果逐位一致；尚未证明完整首次prefill加速。 |
| 融合 GPU 布局转换与有界工作集复用 | shared Expert 跨层更换时，多次转置、临时分配和全尺寸预留侵蚀并行收益。 | 将 canonical→最终 GPU 布局融合为一次 kernel，复用层大小权重及上传缓冲，按实际需求申请 scratch。 | 实机shared up矩阵准备约9.27→1.89ms，布局复用及更换权重校验通过；这是准备成本优化，不能替代未知prompt的端到端收益证明。 |
| 源权重导入后的驻留生命周期控制 | canonical DMA 源已导入后，GGUF 全量预取仍使源文件重复驻留，挤出真正参与计算的权重。 | 按矩阵导入并释放源页引用，关闭未使用 mmap 区域的整体预取，分别统计源表示、转换工作集和输出层恢复驻留成本。 | 开发输入的进程峰值 RSS 由约3.8GiB降至约0.83GiB，logits逐位不变；RSS不含全部DMA，且驻留控制后的整模型首次prefill尚未超过原生NPU。 |
| 有界跨层权重预转换 | 未知prompt首次执行时，NPU内权重重排占据关键路径；转换太多又会阻塞下一层。 | GPU在当前shared完成后，按独立输入训练的逐层先验预转换下一层少量Expert，通过共享DMA双槽交给NPU，未及时命中则按真实路由精确回退。 | 两份新128-token输入各三次首次prefill，较未预取在线异构中位吞吐提高3.50%/4.94%，logits逐字节一致；新增packed容量74.25MiB，但较常驻原生NPU仍为−2.19%/−0.63%。 |
| 混合布局消费与准备生命周期管理 | 缓存命中/未命中拆图、逐矩阵等待和重复DMA导入增加在线准备开销。 | NPU同图按Expert选择canonical/packed源并保留gate/up融合；GPU批量提交转换，模型初始化时建立源DMA别名，首次推理仍按需转换。 | 两份新输入的累计准备时间约162–163→91ms（−44%），ID算子实例90→46、输出不变；相对旧预取端到端为−0.14%/+1.21%，尚无稳定新增吞吐收益。 |
| CPU按Expert分组执行与布局成本匹配 | 低token Expert的通用ID路径不能充分复用多行计算，而首次CPU repack又可能比计算更贵。 | 直接借用单份canonical权重切片，按Expert聚合token走普通矩阵乘，并用开发数据更新CPU分支成本。 | 两份新128-token输入各四轮首次prefill，较原在线异构中位吞吐+1.57%/+5.01%，较同法校准的ID路径+0.94%/+5.17%；整套异构较原生NPU+3.90%/+7.52%，CPU新增权重副本为0。 |
| CPU权重转换中的直接交错写入 | 标量repack的中间block拷贝和子块重排让首次转换吞掉packed计算收益。 | NEON直接读取四行Q4_0量化块，保留scale并融合符号变换、交错和目标写入，保持既有CPU packed格式。 | 两Expert微测的准备约1.6–2.1→0.5–0.7ms，目标4×8布局逐字节一致；完整模型低token尾部仍不及零转换分组路径，保留为可选转换优化。 |

证据：[常驻与共享激活](../task/handoff/handoff-2026-09-24-offline-shared-activation/results.md)、[256-token 消融](../task/handoff/handoff-2026-09-24-shared256/results.md)、[激活池与聚合](../task/handoff/handoff-2026-09-25-activation-arena/results.md)。上述内存数字不是总物理内存上限，固定 prompt 的数值验证也不等于通用模型质量评估。

轻量模型证据：[独立路由与完整模型验证](../task/handoff/handoff-2026-09-26-placement-model/results.md)。当前结果不包含在线权重转换/迁移，不能表述为完整在线调度器收益。

环境校正证据：[新 prompt 完整模型与反馈验证](../task/handoff/handoff-2026-09-26-context-model/results.md)。实际三个长度均选择异构，原生回退仅验证加载功能；256 的新旧映射相同，未显示额外收益。

长度扩展与图内复用证据：[两个新 prompt、768 回退与激活复用](../task/handoff/handoff-2026-09-26-model-extension/results.md)。扩展部署模型 14,369 bytes；所报池容量不代表总额外内存低于 200 MB。该轮存在相对 CPU 的 top-1 差异，需要后续质量评估。

分支准备重叠证据：[host执行与同前缀诊断](../task/handoff/handoff-2026-09-26-host-parallel/results.md)。聚合多线程虽降低局部耗时，但7/8确认进程总均值变慢，未列为成功优化；16步续写验证也表明跨后端存在生成分叉，尚无任务质量等价结论。

联合模型与控制路径证据：[执行策略联合预测](../task/handoff/handoff-2026-09-26-execution-model/results.md)。模型保持约21KB，128/384仍获益；768因校准覆盖与完整模型残差低估而误选，不能将本轮写成“大输入异构负收益已解决”。

误差保护证据：[独立输入校准与完整模型确认](../task/handoff/handoff-2026-09-27-execution-guard/results.md)。约35KB模型保持原计算系数；同一768-token输入的原生时间波动约9.2%，后续需要运行状态感知，尚无DVFS或温度的因果归因。

状态校正证据：[加载前状态与独立prompt确认](../task/handoff/handoff-2026-09-27-runtime-state/results.md)。约35KB模型只对异构路径启用状态系数；768实际仍为原生路径，+2.41%/−0.35%的顺序对照差异不能视为异构加速。此行是有限预测改进，不是已解决在线迁移或运行状态因果归因。

后续动机证据：[HTP窗口与GPU频率诊断](../task/handoff/handoff-2026-09-27-device-timing/results.md)。固定分配下GPU频率均约967MHz，但shared GPU在768-token的345/368个普通层实例中最后完成，128为0/368，说明需要随长度重新平衡shared/routed关键路径；这是一条瓶颈证据，尚非新增优化收益。固定HTP性能请求下，原生耗时差异仍主要出现在DSP执行窗口，不能统归host或调频。

最终封板证据：[联合候选与两份独立prompt确认](../task/handoff/handoff-2026-09-27-final-placement/results.md)。44.8KB模型保留128规则，补齐256/512/768候选；768换成GPU尾组/shared NPU虽缩短计算窗口，却因聚合及非FFN残差增加而更慢。64因覆盖不足回退原生，跨进程变化−3.58%～+4.02%不是异构收益；本轮结束模型优化，仍不主张在线迁移或跨后端质量等价。

用户追加的[64-token校准验证](../task/handoff/handoff-2026-09-27-calibrate64/results.md)：补齐小请求的实测代价与误差余量，按每层负载选择CPU尾组32、剩余routed在NPU、shared在GPU；两份新prompt的完整模型吞吐较原生提高50.1%–63.5%（含决策），而仅将shared移至GPU没有收益。这是64覆盖的新增证据，不是新算法或全长度保证；GPU routed候选因logits稳定性检查失败被排除，该阶段尚未开启300等非锚点长度。

连续长度证据：[区间插值与独立长度验证](../task/handoff/handoff-2026-09-27-length-intervals/results.md)。66.8KB模型支持64–768所有整数长度的候选生成；96/192/320/448/640校准，80/224/300/480/704独立验证，未为300单独拟合。插值本身不单独构成创新性结论，价值在于路由负载、整组并行关键路径和误差保护的联合设计；仍为离线路由驱动的加载前常驻计算。

Decode边界证据：[完整模型分支并行与反向放置](../task/handoff/handoff-2026-09-27-decode-parallel/results.md)。将routed留在原生CPU图、用常驻线程提前启动shared并共享激活，确实形成执行重叠，但128前缀下仍慢于CPU；768前缀仅较CPU改善约0.2%–1.2%，GPU单后端复测又有明显波动。此轮不新增成功加速技术点；可作为“分支独立并不保证收益，decode须比较最佳原生路径并考虑KV、内核与状态”的动机证据。完整shared副本约446MiB，尚非200MB内存设计，也未证明跨后端质量等价。

跨层预转换证据：[首次执行、预测与窗口消融](../task/handoff/handoff-2026-09-28-cross-layer-prefetch/results.md)。当前证据支持逐层热点先验，尚不支持相邻层同编号Expert相似；K12因GPU准备超窗退化，K8较未预取有效但未超过原生。146.01MiB是去除已知源别名重复计费后的局部容量账本，尚非完整额外物理内存保证。

准备流水线证据：[混合布局与首次执行对照](../task/handoff/handoff-2026-09-28-cross-layer-prefetch/mixed-results.md)。四轮顺序平衡对照保留全部样本；源映射建立约34–39ms计入模型初始化并单独报告，新增packed容量仍74.25MiB，局部账本146.52MiB不等于总物理内存。准备减少未等量转化为端到端收益，CPU关键路径与缓存感知分配需联合考虑。
