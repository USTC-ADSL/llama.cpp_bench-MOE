# E0 最终报告

2026-09-08；结论：**PASS，限已约定的设备与工程接受范围。**

模型为 Qwen1.5-MoE-A2.7B-Chat Q4_0。本轮补验设备 fd8657d6（K80 Pro，Adreno 830 / HTP v79），运行时包含 OpenCL 修复提交 `252aa4396`；本轮不修改推理实现。

| 验收项 | 最终结果 |
|---|---|
| CPU 基线与测量 | 沿用后续 E0 报告的工程接受 PASS；原性能数据来自 OnePlus，不冒充 K80 同机性能结果 |
| K80 HTP 默认 HVX/HMX | 四项专家数值、128/32 请求、真实 HMX 路径和计时测量 PASS |
| K80 OpenCL 专用路径数值 | 修复后 n1/n128 gate/up、down 全部 PASS；最大 RRMSE 0.002827，阈值仍为 0.02 |
| 本轮 OpenCL 整模型三模式 | off / observe / enforce 均 PASS；128 输入、32 输出、cache_n=0，32 个 token 逐个一致 |
| 全层放置 | 三模式日志均确认 25/25 层卸载；OpenCL model buffer 7599.83 MiB，未使用 ngl=1 或通用路径绕过 |

本轮固定 c512、单 slot、t/tb4、b/ub128、F16 KV、无 prefix 复用，`-dev GPUOpenCL -ngl 99`。全层卸载不表示没有 CPU 控制/辅助内存：日志仍有 166.92 MiB CPU model buffer。三模式正确性对照使用非约束预算，不是 4 GiB 内成功推理。

原 OnePlus v73 的 HMX 异常未修复，不纳入本次 K80 PASS；原 CPU 严格统计区间仍保留，不因工程接受而改写。这里的 PASS 也不代表多种模型、任意长上下文或跨设备性能排名已完成。

证据：[本轮三模式结果](evidence/final/controls.json)、同目录 `request-*.log.gz` 与产物 hashes；[既有 E0 补验](../E0_followup/report.md)、[OpenCL 数值修复回归](../../bugs/2026-09-08-opencl-q4-moe-repack.md)。原始历史报告不覆盖。
