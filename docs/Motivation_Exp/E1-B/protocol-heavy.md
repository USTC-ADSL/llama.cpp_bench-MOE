# E1-B 较重App补验协议

在任何正式配对前固定；原轻量实验报告/证据不覆盖。用户同意增加两个较重任务，先诊断实际内存再测试，而非通过不断加压追求阳性。

设备fd8657d6；最终使用既有多看阅读器（com.duokan.reader）及小米图片编辑器2.4.0.2.1（com.miui.mediaeditor）。原候选WPS Lite4.0.4首次启动要求接受协议，选择退出、改用多看。编辑器选择“不同意”联网协议，仍可本地编辑。只打开新生成的明确带E1-B标记的实验文件，不访问私人文档/相册或登录账户，不安装App、不清数据。

初始任务素材固定：160页1536×2048独立栅格PDF（约116MiB，所有页均有页码标记）；8000×6000的48MP JPEG（约14MiB）。确定性生成代码在tests/run-e1b-heavy.py，固定seed20260908；源文件SHA256在evidence/heavy/assets/manifest.json。大文件不等于大驻留，不能仅凭文件大小称为重内存任务。

探索/诊断阶段：确认可直接打开指定素材及可复现操作；PDF保护非首页阅读位置，图片保护未保存编辑并验证后续导出。独立测量App准备前/任务就绪/后台内存（App PSS/RSS与MemAvailable分别报告，不把口径叠加）。若因降采样/流式文档导致内存仍低，报告实际数值，不自动扩大文件或增加不相关压力。

正式前追加固定的具体操作及状态判据。两App分别与原最佳B1全层OpenCL（-ngl99、相同512/128、c2048等）做3组noLLM/LLM配对，AB/BA/AB；未参与的本实验App退出。主要任务在模型加载前已后台。沿用原额外reload或切回+500ms AND +50%的degraded门槛；状态丢失/任务中断/10s不能恢复为fail，同类新增影响≥2/3才称可复现。切回以设备monotonic证明发生在推理中；原ADB优先级边界继续适用。

延迟测量与PSS诊断分开；正式仅原安全watchdog，不改LMKD/swap/频率/配额，不清缓存/不加匿名内存压力。真实失败/退化是结果，不重跑筛掉。初始任务尚不能安全自动化时，只修复准备流程且保留失败；需要新授权则暂停询问。新证据evidence/heavy，远端仅/data/local/tmp/llama-e1b-heavy和/sdcard/Download/E1B-heavy。最终清理本任务文件，保留用户数据。

## 正式配对前锁定的实现细节

- PDF：多看仅确认复制外部传入的本实验文件，不加书架。依次拖动固定进度到x350/x700/x540，最后保护81/160页；恢复后验证同页，再操作既有进度条到后续页证明能继续阅读，不重新发文件打开Intent。
- 图片：原48MP素材打开本地标记工具，沿固定坐标画红色对角线（两次同路径，以消除首次提示层影响）。保护可保存/可撤销的未保存标记；恢复后通过新截图红色像素检测，按保存并拉回该实验进程实际导出的副本，检查8000×6000及红色标记。副本由编辑器写入DCIM/Creative，限定日志识别的精确新文件清理，绝不删除该目录其他内容。
- 文件入口：仅登记两份测试文件MediaStore记录，ID由精确_data查询，授予所选文件URI读取。初版.nomedia导致图片记录变为非媒体，已删除本实验的空标记并修正流程，无全盘权限授予。
- 回前台方式：无URI的am start会使多看跳转主界面，已在无LLM预演发现，不计内存失败。改用shell app_process调用startActivityFromRecents恢复明确task id，不发新Intent、不设置优先级、不改系统策略。辅助Java源码与DEX哈希保留。
- 返回计时：设备System.nanoTime/CLOCK_MONOTONIC在恢复调用前记录t0，随后读取已有HWUI framestats，取IntendedVsync≥t0且Flags=0的首个FrameCompleted，得到first_frame_ms。这是应用新帧完成，不是整个屏幕呈现/完整内容加载保证；另有实际页面/标记状态验证。dispatch_ms只是Binder调用时长，不作为体验指标。没有有效帧记录时计时不成立，不用dispatch替代；状态仍独立记录。
- noLLM等待46s，与原B1选择规则一致；两侧任务切回目标为请求/对照起点后1s，实际通过设备时钟验证。图片状态截图检查在请求内完成后立即保存，需核对保存触发也与推理重叠；完整输出文件读回和日志验证放在请求结束后。PDF返回状态采用UI页码核验；性能阶段不采PSS，gfxinfo只读现有帧数据，工具开销两侧一致。
- 初步独立PSS：PDF就绪约321MiB/后台257MiB；图片就绪172MiB/后台110MiB。大素材的常驻内存仍不高，不能称持续重内存负载。实际48MP导出独立采样15点峰值1096104KiB（约1.045GiB），导出正确；不是严格瞬时峰值上界。正式中不按观察结果继续扩大素材。
- 仅两个新任务各3对AB/BA/AB，不自动追加组合或匿名压力。原轻量结果保持；新实验可能仍不支持H1-R，必须报告按需加载/降采样与短暂导出负载的边界。
- 正式全局顺序在开始前固定为image三对→pdf三对。完整noLLM预演image-2、pdf-1均状态/继续操作通过，first_frame约34.031/46.509ms。recovery_upper_ms含UI dump/截图/检查开销，仅是状态确认上界，不以其>10s单独认定App无法恢复；该10s内容恢复项若证据不足须明确不下结论。
